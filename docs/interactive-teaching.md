# 交互教学与内置系列课

## 用户入口

从「新领域 → 交互教学体验」打开课程。首次安装和旧版本升级会补入四个分类会话：结构与过程、数据图表、互动练习、图像与综合。时间轴和结构图归入「结构与过程」；需求预测、折线、柱状、面积、散点、瀑布、评分矩阵、区间与公式归入「数据图表」；答题、翻卡、排序和小游戏归入「互动练习」；图片热点与数据观察、文字、判断题与杠杆实验的组合归入「图像与综合」。四个会话之间没有先修限制，每个会话已有标为「内置示例」的本地教学消息，无需 API Key 即可操作。

旧版本曾把每种示例拆成独立课时。升级时只合并未改名、未改写目标且没有追加对话的内置旧节点，并把已保存的互动状态迁移到对应分类会话；用户编辑过的名称或目标、包含个人追问的旧会话继续保留。若用户此前删除了「新领域」，首次补入时使用仍存在的第一个方向；没有方向时创建一个。

应用不会在普通启动或覆盖安装时自动复活整门演示课程。用户打开「新领域」后，缺失状态会显示一次「恢复演示课」操作；点击后只清除内置课程及其组件标记并重建四个分类会话。其他学习记录不受影响，重复点击也不会产生重复课程。

点击节点、切换维度、选择数据、调整价格、翻卡、移动排序、点击热点和提交预测均由原生 Compose 执行。排序可长按拖动，也提供上下移动图形按钮；图片热点支持单独查看。数据图表与变量实验台显示放大入口；小游戏只在点击“放大游玩”后运行，其他组件不重复提供无必要的放大操作。放大后与主对话共享状态，系统返回先关闭图示。组件右侧重置只清除该组件的互动状态。普通组件状态在本机加密保存，重开课时后保留。小游戏只保存是否打开过的体验记录，不保存任意代码的局内状态；每次打开、重开或旋转屏幕都开始新局。

放大视图使用带外部遮罩的近全屏大圆角卡片，保留系统安全区，不占满整个屏幕。热点采用18dp可见数字与48dp透明触控框，边缘触控框约束在图内；不让点击范围决定遮挡面积。选中颜色使用180ms过渡。组件内容高度使用220ms过渡，时间轴按行展开，其余组件在卡片外层统一协调；不逐帧写入数据库。翻卡同时测量两面并保留较高面的高度，隐藏面不参与点击和读屏。

知识翻卡只由卡内“翻面／翻回”按钮驱动，使用 520 ms 的 Y 轴三维翻转；拖放排序使用 Apache-2.0 的 Calvin-LL Reorderable 3.1.0，按住拖动点后直接移动并让其他条目平滑让位，同时保留上下移动按钮供无障碍操作。

内置示例是预置教案，不是实时模型回复。继续追问仍需要配置模型，必要的组件内容和互动摘要会随近期对话发送给所选服务。AI 可自行组合文字与组件，用户也可要求「用时间轴讲」「用表格对比」等。仅提供 JSON 数据的自定义模型同样可以使用；组件数据不合法时保留独立可读的文字讲解。

## 协议与边界

`AiProtocol.tutor` 在原有 `reply`、`kind` 之外接受可选 `blocks`。当前支持 `text`、`timeline`、`figure`、`matrix`、`range`、`funnel`、`formula`、`chart`、`quiz`、`flip`、`sort`、`hotspot`、`experiment`、`game`（`quadrant` 自 0.15.20 起停用，`compare` 自 0.15.25 停用、`flow` 自 0.15.27 停用；三者旧快照仍可解码但不展示、不生成；流程与比较分别改由 reply 里的 mermaid 围栏与 Markdown 表格承担）。`chart` 另有 line/bar/area/scatter/waterfall 五种样式。`reply` 始终必填，既是概括也是组件降级时的阅读内容。实时模型提示词要求最多3个组件；持久化解码器允许一个内置分类会话最多16个组件，防止后续同类示例增加时再次拆节点。组件 ID 在一条消息内唯一，状态以消息 ID＋组件 ID 定位。

模型先生成课程时，会按主题设计不同的认知动作，目标避免只写“了解、熟悉、掌握”，而会明确比较、读图、排序、分类、回忆或推演等可检验结果。具体教学回复再根据本节目标选择组件：时序用时间轴，分支流程直接写成 reply 里的 mermaid 代码围栏，易混概念用正文里的 Markdown 表格逐项对比，定量变化用图表，记忆条件用翻卡，连续顺序用排序，类别判断和计算推演采用文字或适用的现有组件；热点用于位置关系对理解有帮助、图中确实包含目标结构的观察任务；当前仅限植物细胞结构。只讲功能、术语记忆或分裂过程时分别考虑文字、翻卡或流程，不强制使用热点。提示词列明模板坐标并建议每轮聚焦2–4个结构，区分示意图与真实显微照片。没有匹配意图时只输出文字，通常使用0–2个组件，避免把同一信息重复包装成组件。

对 DeepSeek Flash 的历史、数据分析、操作流程、语言和植物细胞五个主题实测及误用修正见[组件主题选择实测](component-selection-audit-2026-11-21.md)。

`TeachingBlockProtocol` 限制总长度、数组数量、文本长度、有限数值、引用和题目选项。流程与前文共用 `LessonFlow` 解析、原生排版和回环处理：围栏内容先按流程图解析，再退回字符图或代码块。排序必须给出不重复且完整覆盖所有条目的正确顺序。热点只接受应用内置的 `plant_cell` 图像模板和 0–100 百分比坐标，不接受模型图片 URL。未知类型或无效组件逐个丢弃，不能执行代码、打开资源或发起业务操作。只有合法game的code可进入下述专用Worker运行器，不在原生宿主中执行。数据库中保存生成时的组件快照，更新教案不会改变旧消息的题目和判定依据。

`chart/data` 支持2–12个数据点，标注横纵轴和单位，可点选曲线节点或下面的数据项。任意数据图表都可带 `prediction`：先显示预测题，学生选择并点“验证预测”后才展示图表，用于涨跌、峰值、是否交叉这类有客观对错的判断。`chart/linear_demand` 是应用实现的固定模板 `Q = 120 − 10P`，P为2–10元，同样可带预测题；数量单位由可选 `quantityUnit` 明确（如杯、件、张），缺省显示「单位」。固定模板的横轴始终为需求量、纵轴始终为价格，避免模型把坐标标反。滑动过程中只更新页面数值，松手才写入状态。该模板仅用于其他条件不变的需求教学，不是任意公式引擎或现实销量预测。

`experiment/lever` 是应用内置的理想轻杆实验。AI只提供 `prompt` 和 `initial`（`leftForce`、`rightForce`、`leftArm`、`rightArm`），不生成代码或任意公式。两侧力为竖直向下的1–10 N整数；力臂是到固定支点的水平距离，1–4 m、步长0.5 m。应用比较两侧 `F × 水平距离`，不计杆重、摩擦和动态振荡。倾斜仅表示哪侧下沉，不表示真实运动或静止角度。

实验支持水平拖动重物调整力臂，也提供四个有名称与单位的滑块。预览只修改本地状态，松手后提交单字段动作，仓库事务将它合并到最新参数，避免快速调整不同控件时互相覆盖。放大、退出、重开与重置沿用相同组件状态；宽屏放大时采用场景与控件左右分栏，窄屏纵向排列；`TeachingState.lever` 是现有加密JSON内的可选字段，旧记录缺少时使用教案初值，不改变Room schema。Markdown导出记录实验假设、初始配置与实际互动摘要；AI历史接收实际参数和计算结果。

内置杠杆实验以安装标记1021追加至 `visual` 会话。升级只追加未安装的新组件，仍遵守用户删除优先，不覆盖旧目标和消息；不恢复分类或分步推演组件。

### 结构图 figure

`figure` 由若干行组成，每行要么是 1–3 个并列节点，要么是一句关系说明，末尾可带一句脚注。它承载“由哪些部分组成、谁对谁负责、几项并列但有主次”，不承载因果流程（写成 reply 里的 mermaid 流程图）；两个对象的逐项对比放在正文的 Markdown 表格里。

- 节点只有 `title` 必填，`value`（短数字）、`note`（一句限定）、`items`（最多 2 条短语）、`tone` 可选。
- 校验：行 1–6、每行 1–3 列且节点数必须等于列数、`title` ≤20 字、`value` ≤8 字、`note` ≤40 字、脚注 ≤120 字；语气色只允许 blue/amber/rose/teal，未知值整块丢弃并回退文字。
- 列宽由 `weight` 均分；三列时内边距收窄、字号不变，不做“窄屏降成单列”，保住并列语义。
- 语气色只用于区分类别，每图最多两种，不代表对错。
- 读屏只念一次结构摘要（各节点标题、数字、关系句与脚注），不逐节点跳读。

### 矩阵、区间、漏斗与公式

- `matrix`：行 2–6、列 2–5、分值 0–5，行数与列数必须和 `values` 的二维数组一致。颜色只表示分值高低，不表示对错；评分依据写在 reply 或 caption。
- `range`：`min`/`max` 是整条轨道，`low`/`high` 是有把握的区间，`value` 是当前估计，`unit` 不超过 6 字。低值必须不大于高值，当前值必须落在轨道内。
- `funnel`：`mode` 为 `funnel`（逐级递减）或 `pyramid`（逐级递增），2–5 层，`ratio` 5–100，方向反了整块丢弃。
- `formula`：1–6 行，每行一个式子，支持 `frac{a}{b}`、`sqrt{x}`、`x^{2}`、`a_{i}` 与直接书写的 × ± ≤ π 等符号。应用只排版、不求值，解析失败时按原文显示。
- `chart/style=scatter`：每个点必须同时有 `x` 与 `value`，横轴用真实 x 值缩放，只画点不连线，避免暗示未计算的趋势。
- `chart/style=waterfall`：首尾两点必须标 `total: true` 且写绝对量，中间是可为负的增减量，共 3–10 个点；累计基线由应用计算，模型只负责给增减量。
- `quadrant`：`x`、`y` 都是 0–100，`quadrants` 四个名字按左上、右上、左下、右下排列，点 1–8 个且 id 唯一。拖动后的坐标按消息与组件写入加密状态，重置后回到模型给的初始位置。

这四个块都是纯展示：不参与互动状态、不显示重置与放大，也不计入课时完成。

### 小游戏协议与运行边界

`game` 包含 `goal`（最多240字符）、`instructions`（最多160字符）、`code`。AI根据本阶段是否需要“操作→观察→调整策略”判断是否生成；简单定义、普通追问和其他组件足够表达时不放小游戏。**不生成换皮选择题**：用按钮选答案、把文字选项归类或判断对错的玩法与随堂答题、排序重复，一律不用。玩法优先要求实际动手，例如拖动归位、配对连线、拼装组合、调参到目标、规划路径、分配资源、把握时机。代码目标2400–8000字符，硬上限16000个UTF-16单元（含空白），每条实时回复最多接受一个game；超长组件丢弃，保留reply降级正文，不截断脚本。提示词同时要求分层写法：状态集中在一个对象、移动/碰撞/计分/胜负各写成命名函数、`draw` 只按状态拼命令，禁止一行流与压缩赋值，避免为省字符写出重复计分、卡死或越界这类隐蔽 bug。

统一底座提供 `draw`（0–100逻辑坐标，最多512条命令，支持 text/rect/circle/line/poly/arc，含文本对齐与加粗、矩形圆角与描边、`#RRGGBBAA` 透明度）、`say`、`buttons`（最多6个，只用于重开、下一步等辅助操作）、`onPointer`（down/move/up 拖动）、`onTap`、`onAction`、`onFrame`（宿主按约30帧/秒驱动，用于进度、计时与位移动画）、`finish`，以及可选的 `background` 与 `hud(false)`，让游戏自绘底色与标题、进度，从而摆脱统一的卡片外观。画布铺满可用区域，横纵按比例伸展，圆形与文字按短边取尺度，避免被拉成椭圆。代码以Base64数据注入独立Worker，不拼成宿主页脚本或HTML；页面绘图和按钮只处理有界数值和纯文本。Worker启动2400ms、单次输入1500ms超时后终止，每局最长120秒，限制消息频率（200条/秒）与消息长度（64KB）；语法错误显示重开提示。原生重开与关闭按钮始终位于WebView外。拖动事件不占用忙碌标记，按约30次/秒合并移动；帧回调上一帧未返回就不再发下一帧，慢脚本自然降帧。

WebView无JavascriptInterface；禁止网络、文件、content访问、DOM存储、弹窗、下载和权限请求。CSP禁用连接、导航、表单与外部资源；原生再次拦截导航和资源加载。Android 29+响应渲染器无响应时终止，并处理渲染器退出。关闭销毁WebView，后台暂停终止当前Worker。模型代码既不能点亮课时，也不能通过游戏反馈影响正式评估；本机只记录“已打开”，不把胜负当成可靠成绩。宿主页不接收API Key、个人资料或聊天原文。代码快照随原有加密教学JSON保存；发给AI的历史只包含游戏目标、玩法和体验摘要，不重复发送源代码，Markdown导出也不附脚本。

示例以标记1022追加到 `practice` 会话。对比卡自 0.15.25 起停用，内置结构与图像会话不再安装对比卡示例；升级只清理与旧教案完全一致的methods/travel配色演示，标记1003/1007/1008永久保留、不再复用。

所有新旧课程共用当前教学协议。重新学习会清空旧对话，提示词会从笼统的旧goal推导认知动作，优先用适配的表格、时序、mermaid 流程或图表；没有匹配意图时仍允许纯文字，不强行补组件。真实DeepSeek样本和验证边界见[小游戏与旧课程实测](teaching-game-audit-2026-11-21.md)。

随堂题和翻卡支持 1–3 级提示阶梯：错误提交先显示第一级方向性线索，学生可逐级点“再给一点提示”，最后一级接近方法但不直接给答案；提示层级随组件状态加密保存，重置后回到第一级。旧快照只有单条 `hint` 时按一级处理，不做批量改写。随堂题、排序和翻卡统一遵循“先提示、允许重试、由学生主动查看完整答案”：更改答案或顺序后可再次提交；只有点击“查看完整答案”才显示解释或正确方案。重复提交不增加次数；答对后锁定，重置后可重新体验。它们不调用 `lightFromAssessment`，不占正式题号，也不修改课时完成或发证资格。正式课后练习继续走原有 `kind/question/choices/exerciseId` 状态机；待答正式题期间不接受新教学组件。

`TeachingInteractions` 是纯领域状态转换器。UI 只转发动作；`ChatViewModel` 串行提交互动并在发出追问前等待已提交动作；`ConversationRepository` 在事务中重新读取消息、校验归属、版本、解锁状态和组件引用，再加密写回。消息或课时删除后，迟到的动作不能重建内容。

Room v13 给 `turns` 增加可空的 `teachingBlocks`、`teachingStates`，分别按消息 ID 绑定 Android Keystore 加密。v12→v13自动迁移，旧消息读取为空组件。导出的 Markdown 保留图示内容、数据与互动摘要；未作答的题不主动导出答案。模型上下文超过组件预算时使用有界摘要，避免大组件把整条近期消息挤出上下文。

## 增加一种交互时按类别收纳

1. 在 `model/TeachingBlocks.kt` 增加类型及必要的纯状态转换。计算模板需要明确输入边界、单位、假设和验证用例。
2. 在 `ai/TeachingBlockProtocol.kt` 增加编解码、数据约束、模型提示词；保持未知类型降级和文字兼容。按需要更新模型历史摘要与 Markdown 导出。
3. 在 `ui/TeachingContent.kt` 注册原生渲染器；复杂组件可放入独立 UI 文件。复用现有颜色、控件和弹层，确保触控目标、读屏名称、滚动及系统返回可用。图形按钮必须使用固定版本 Lucide 资源。
4. 在 `model/BuiltInTeaching.kt` 选择「structure、data、practice、visual」中的一个分类会话，向 `items` **追加一个带独立安装标记的组件**。现有分类课时标记为2001–2004，组件标记1001–1020已经使用，杠杆实验已使用1021，小游戏已使用1022，结构图已使用1023，矩阵1024、区间1025、公式1026、漏斗1027、散点1028、瀑布1029已使用（四象限1030已随组件停用），后续从1031继续分配。只有确实引入不属于这四个类别的新交互时，才新增分类会话和新的稳定 `key`、标记。
5. `LibraryRepository.initialize` 会在保留的分类会话中追加缺少的组件；若会话存在但示例消息被清空，只创建一个包含新组件的内置消息，不重建已删除的旧组件。不会覆盖用户对课时的编辑，也不会自动重建用户删除的课或课时。用户删除整门课后，只有从「新领域」主动选择「恢复演示课」才会执行事务化恢复。
6. 补领域、协议、存储和迁移测试，并在模拟器验证触控边界、横纵滑动、键盘与系统返回。每种新增类型都应在同一课程中有可离线体验的验收样例。

## 正文排版规则

普通教学回复与 `text` 组件都由 `LessonMarkdown` 渲染，字号、行高与间距集中在 `ui/LessonTypography.kt` 的 `LessonType`：标题 20sp、兜底小标题 17sp、正文 16sp / 27sp 并启用等宽数字（`tnum`）、引用 14.5sp / 24sp、嵌套列表 15sp、等式 15sp semibold。块间距分级：标题上 18dp / 下 6dp，段落 16dp，列表项 12dp，嵌套项 4dp，引用块内 6dp；列表符号按首行行高居中的 5dp 圆点，嵌套为 4dp 次级色圆点。节奏来自“块间松、块内紧”，不是整体加行距。

引用块由左侧 3dp 主题色竖条 + 7% 主题色淡底构成，正文降一档并转次级色，用于模型输出的“提醒 / 易错点 / 概念区别”。自 0.15.26 起不再要求每条回复必须出现引用，是否使用、用几个由模型按内容决定，渲染层不做数量限制。标题与正文之间的间距不对称（18/6dp），标题因此贴住自己所属的正文。

换行归一化会保留列表项与引用行内部的单换行：此前把每个列表项都拆成独立段落，会让有序列表重新从 1 编号、列表节奏散掉；模型常用的 2 空格嵌套缩进会被补到 3 个空格，否则有序列表的子项会掉出列表。

Markdown 表格按卡片排版：白底、1dp 描边、14dp 圆角；第一列当作维度列收窄到 78dp、12.5sp 次级色，其余列等宽分配、13.5sp / 21sp 并启用等宽数字；表头 13.5sp semibold，表头下方一条实线、行间只有发丝线。2–3 列的表格收进卡片宽度，不再横向滚动；4 列以上才保留横滑（单元格固定 118dp），避免每列被压成一条。表格本身仍来自模型输出的 Markdown，没有新增协议或组件类型。

三条纯文本规则负责在不依赖模型的情况下稳定层级：

- **等式行**：整段是“短名词短语 + 等号 + 表达式”、不以句末标点收尾且不超过 80 字时，脱离项目符号单独排成淡底色等式块（15sp semibold），列表项若是纯等式也不显示圆点。
- **运算符规范**：仅在算式段落内把 ASCII 减号换成 `−` 并留白，数字之间的运算符用不换行空格粘住，避免算式被行尾拆开；`2024-01-05` 这类日期原样保留。
- **兜底小标题**：2–24 字、以“：”结尾、不含句号和等号的独立短段升为 17sp semibold 主题色并额外上留 4dp。

规则都只在识别成立时生效，不成立就按原正文渲染；判定函数 `formulaCandidate`、`subheadCandidate`、`normalizeEquationOperators` 与换行归一化均有单元测试。等式块不会改变模型原文的语义，也不改写存储内容，只影响本机显示。同一段回复改用分级间距后整体高度基本不变，因为标题与引用同时降了字号。

## 配色与图表样式

对比卡已停用，配色枚举仅用于解码旧快照，不再生成。

数据图可选 style：line（默认折线）、bar（柱状）、area（面积）。样式不改变原始数值、单位与点选状态；柱状图围绕零基线绘制，面积图闭合到零基线，不自动累计数据。需求模板始终使用折线。旧消息缺少可选字段时沿用默认样式，未知字段值降级到默认，无需数据库迁移。

时间轴采用贯穿各行的连续线与选中节点光环，展开详情不会打断轴线。内置不再安装对比卡示例，AI 也不再生成；三种图表样式共用「数据图表」。旧版独立示例升级后不再作为新节点重复出现；用户编辑过的旧节点和包含个人追问的会话保持原样。
