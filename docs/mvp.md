# MVP 技术设计

## 架构与数据

单个 Android 应用模块使用 Kotlin、Compose、ViewModel 和 Room。页面通过 ViewModel 观察仓库。Room 统一保存三层项目、前置关系、对话与进度。父级外键级联清理子项目、关联边和所属对话。首次启动的种子记录与初始化标记同时写入，因此用户删除预置方向后不会被重新创建。

技能点可以依赖同树的多个节点。手动保存与 AI 生成共用有向图校验和最长依赖路径分层。地图支持双轴平移和双指缩放。点亮来源区分手动和 AI 评估，用户可取消点亮。

技能地图对层内节点重新排序，跨层连接经过层间独立通道。同一层间只绘制端点顺序相容的连线，允许分叉与汇合。其余依赖使用成对编号和关联列表呈现，前置关系仍按原数据保存。

数据库 v2 增加可空的图标、地图简称和选择题选项，Room 从 v1 自动迁移。旧项目按层级使用默认图标，地图简称从完整名称派生。手动选择和 AI 推荐共用同一套本地图标。

外观设置单独保存在本地，默认自动跟随系统。Compose 组件、画布、教学图表与系统栏使用同一主题选择。

API Key、用户输入的技能名称和目标、对话正文均使用 Android Keystore AES-GCM 加密后保存。数据库仍保留索引所需的层级、关系、状态和标识。项目关闭系统备份及设备迁移的数据提取。

## AI 请求与本地状态

- 使用 OpenAI 兼容的 Chat Completions 接口进行非流式请求。DeepSeek 使用 JSON Output，MiniMax 和自定义接口通过提示词请求 JSON。模型思考内容不进入会话历史。网络层拒绝明文请求和重定向，避免把密钥发往另一个地址。
- 生成对话分为全局、方向和树三种作用域。全局可新建方向，或为已有方向新建树。方向内新建树，树内追加节点。每个入口只给模型展示当前层级的写入格式。模型只能提出新增操作。App 拒绝截断、重复键和嵌套过深的响应，仓库继续校验层级、同级重名与依赖边。新增内容和结果消息一并提交。
- 每条待处理消息有稳定标识。生成数量越界时，App 按原请求补做一次并重新校验。重试沿用同一标识，完成的回复在事务中去重。失败保留输入，用户可重试或撤回编辑。若对话归属在请求期间被删，迟到的响应不再写入。
- 节点对话只发送当前学习目标及该节点近期消息。App 创建练习标识，只有当前练习有新回答且模型返回匹配的通过结果时才写入点亮状态。修改节点内容使旧练习失效，评估期间的手动状态操作优先于迟到的结果。回答的质量和是否跑题由模型判断。
- 教学提示词默认先讲解，两轮讲解后才提示可主动出题，用户主动检验可以随时出题。选择题选项和对话正文一同加密保存。Markdown 和表格由 CommonMark 解析，简易纵向 Mermaid 流程图使用原生 Compose 绘制，其他 Mermaid 语法显示源代码。
- 「重新学习」在原会话追加新一轮标记。模型上下文、主动提问节奏和待答练习从标记后重新计算，继续使用最新提示词、技能说明和本次学习要求。旧对话与点亮进度保留，迟到的旧回复不会写入新一轮。
