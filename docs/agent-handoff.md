## 产品现状

LifeSkill 是单模块原生 Android 学习应用，使用 Kotlin、Jetpack Compose、ViewModel、Repository 和 Room。主要流程如下：

- 学习按「方向 → 课程 → 课时」组织。课时支持同树先修关系、分叉上限、解锁、学习、课后练习、重新学习和对话导出。
- AI 生成课程先进入对话草稿，用户确认方向后才写入课程库。DeepSeek、MiniMax 和自定义 OpenAI 兼容服务可填写用户自己的 Key；请求使用 HTTPS，拒绝重定向。图片识图使用内置多模态模型，文档与 PDF 在本机提取后发送必要正文。
- AI 老师支持 Markdown、表格、Mermaid 原生流程图、附件、联网搜索、深度思考和用量统计。迟到回复不能在记录删除后重建内容。
- 结业考试固定为 10 道选择题（6 单选 + 4 多选，0.15.34 起不出填空），60 分通过；通过后可领取冻结快照证书，并体验「查漏补缺」「费曼复述」。
- 用户内容、API Key、对话、附件、教学状态和证书档案通过 Android Keystore 加密。系统备份与设备迁移的数据提取已关闭。
- Room 当前版本为 v13，逐版本迁移和导出 schema 必须保留。

完整业务规则见 [MVP 技术设计](mvp.md)，代码入口和持久化约束见[架构与代码导航](architecture.md)。

## 交互教学现状

「新领域 → 交互教学体验」是四类离线示例课程，不是十节独立课时：

| 稳定分类 | 已有内容 |
| --- | --- |
| 结构与过程 `structure` | 时间轴、结构图、漏斗（流程图、四象限与对比卡已停用） |
| 数据图表 `data` | 需求预测模板、折线图、柱状图、面积图、散点图、瀑布图、评分矩阵、公式（区间条已停用） |
| 互动练习 `practice` | 随堂答题、知识翻卡（均支持 1–3 级提示阶梯）、拖放排序、可拖拽的短小游戏 |
| 图像与综合 `visual` | 植物细胞图片热点，参数实验台（AI 定义参数与结果，内置杠杆/复利示例），以及数据观察、文字和判断题组合 |

模型教学协议当前支持 `text`、`timeline`、`chart`、`quiz`、`flip`、`sort`、`hotspot`、`experiment`、`game`；`compare` 自 0.15.25 停用、`flow` 自 0.15.27 停用、`range` 自 0.15.32 停用，旧快照仍可解码但不展示、不生成，逐项比较改用 Markdown 表格、流程图改用 reply 里的 mermaid 围栏。实时回复最多 3 个组件；提示词要求通常使用 0–2 个并避免重复表达。组件正文始终保留为降级内容，未知或无效组件不能执行代码或发起业务操作；game.code仅进入受限Worker，无原生宿主接口。

新增同类组件时追加到现有分类会话并使用新的安装标记；只有新的交互类别才新增课时。不得为同类组件重复建节点，不得覆盖用户编辑，也不得自动复活已删除的课程或组件。用户可以从「新领域」主动恢复整门演示课。详细协议、状态机、稳定 ID 和扩展步骤见[交互教学与内置系列课](interactive-teaching.md)。

## 0.15.39 的验证证据

- 目标：把界面里"状态一变就硬切"的地方按苹果那种细腻、克制的标准补齐，同时保证一套语言、跟手可打断、不付性能代价、不引入新问题。
- 语言：新增 [Motion.kt](../app/src/main/java/com/lifeskill/app/ui/Motion.kt)，五档时长（90/150/220/320/520ms）+ 三条曲线（标准/减速/加速），提供 `contentSwap`（换内容）、`expandFade`/`shrinkFade`（展开收起）、`appearFade`/`disappearFade`（父级已管高度时只淡入淡出）、`rememberPressScale`（主操作按压回弹）。原有散落的 120–720ms 自定时长与 `FastOutSlowInEasing` 全部改取令牌，规则写入 [动效语言](motion.md)。
- 补齐的换场：首页学习卡换挡（未开始/继续/已完成，文案+插图图标+主操作）、方向卡底部三态、聊天选项作答后收起、考试四阶段、证书三面板、练习页尾换题、判分与热点详情、附件来源、表单展开区、余额查询状态链、启动页退场。
- 修掉的瞬跳：底部标签选中色、选项与单选/勾选底色、进度条（任一卡片统一补齐）、进度与统计数字（`ChangingText`）、放大图示与重学遮罩无进场动画、地图/证书/附件列表增行。
- 约束验证：新动效只用 alpha 与 `graphicsLayer` 变换；换内容的尺寸动画只保留一个主人（`animateContentSize` 与 `SizeTransform` 不叠加）；所有 tween/spring 走 Compose 动画时钟，系统「移除动画」时直接落终态。
- 性能：长内容滚动（交互教学页内滚动，Pixel 9 Pro 模拟器 + Apple GPU/Metal）改动前后同机对比——改造后 212 帧 / jank 4.72% / p50 17ms / p95 23ms；基线 210 帧 / jank 6.19% / p50 17ms / p95 23ms。软件渲染（SwiftShader）下只能做相对比较，未作绝对帧率结论。
- 测试：`assembleDebug`、`testDebugUnitTest`、`lintDebug` 通过。仪器测试全量 152 项中 11 项失败，基线同一环境为 16 项失败，失败集合为本项目既有的顺序依赖问题（每个用例单独运行均通过，例：`homeCreatesTreeAndLeadsToNextSkillThenCompletedMap`、`directionColorChangesItsIconAndProgressTogether`）；`TeachingUiTest` 14 项全通过；改动相关 8 项定向回归 7 项通过，`showsFourCertificateThemesWithoutScores` 在基线上同样失败（销毁证书禁重签的断言），与本次无关。

## 0.15.38 的验证证据

- 反馈：用上传文档生成课程时，AI 应熟读文档、生成依托原文件的课程，而不是随意发挥；追问可适度拓展；开联网搜索与深度思考时同样尽可能依托原文。
- 课程生成（`AiProtocol.generationPrompt`）：先通读全部资料再规划，理清目录/章节/条款/表格/附录与强制要求、条件例外、示例的差别；每节课的 sourceNotes 必须能指回具体章节条款并记录要求、数值、单位、步骤、例外；原文没有的内容只能标为补充，冲突以原文为准；partial 附件只覆盖已读部分并说明缺失；未确认生成时的 reply 要点明依据的文件与覆盖范围；搜索与深度思考不得改写原文要求。资料规则原先只在新建课程时生效，现在追加课时也包含。
- 讲解（`tutorPrompt`）：有 sourceNotes 时先讲原文要求、条件、数字与例外，再说明怎么用，并据此出题判分；追问允许拓展背景、类比与反例，但须标明是补充，不冒充原文条款；搜索结果与原文冲突时以原文为准并指出差异。
- `SOURCE_NOTES_LIMIT` 480→800：课后讲解只能看到这份摘要，原文里每节的要求与数值需要能据此复述。提示词同步改为“3–5 句”。

## 已知边界与限制

- 小游戏为点击与拖动驱动的短回合游戏，单个code最多16000 UTF-16单元，每轮最多一个game；放大才运行，后台/退出/旋转结束当前局，局内状态不持久化。启动2400ms/输入1500ms超时、64KB消息预算与120秒局长限制由运行器执行。错误脚本可重开或关闭，不把结果当作正式评估。运行器不提供键盘、音频与网络，动画帧由 `onFrame` 以约30帧/秒驱动；`100vh` 在部分系统 WebView 会被解析为 0，页面改用实测视口高度，改动布局时不要退回百分比高度。
- 小游戏不允许生成"按钮选答案/文字归类"的换皮选择题，此类内容应使用随堂题或排序；提示词约束无法在运行时强制判定，仍需抽样检查模型输出。
- 游戏运行测试使用Android 16系统WebView；Android 8–9保留资源/网络限制和Worker超时，原生渲染器无响应终止回调仅Android 10+可用。没有在真机或所有WebView版本验收。
- 老课程不存在创建时间门槛；已加强适配组件的提示词，但不能据四个样本保证任意课程、模型、轮次都生成组件。

- 参数实验台 `experiment` 已是通用组件（`v0.15.35` 起）：由 AI 判断当前主题适合调参后，当场定义 1–4 个参数、1–3 个结果表达式与初始值；应用只用受限求值器（数字、参数、四则、乘方与白名单函数，表达式 ≤300 字符、嵌套 ≤24 层、结果有限且 ≤1e12）算数值，不做物理仿真、秤杆动画或预置模型分支。杠杆与复利只是两份内置示例数据，用来示范「AI 应该怎么写」，不是等着匹配案例的模型。旧快照里的 `model`/`lever` 字段在解码时映射成等价参数表。参数表、默认值与表达式能否算出全部结果由原生协议校验；AI 是否会为某个主题选对参数与表达式，仍需抽样检查模型输出。

- 分类与分步推演已按用户要求停用，旧加密快照保留兼容。旧课时名称、目标和消息正文不批量改写，因此旧目标中可能仍有历史组件文字，但卡片不再显示。

- 本次平滑性验证覆盖布局尺寸、实际交互和动画推进，不是帧率基准；模拟器 Debug 渲染统计不能代表真机表现，尚未完成真机帧耗时测量。本次对旧课与小游戏进行了四个真实模型请求；停用组件仍有本机过滤兜底。
- 组件选择只对 DeepSeek Flash 的五个主题做了针对性实测，不能据此宣称所有模型、所有学科和所有课程长度都能稳定选对组件。
- 图片热点目前只支持内置 `plant_cell` 植物细胞模板，其他空间主题不能传入模型图片 URL。
- 演示课和组件遵循用户删除优先。覆盖安装不会自动恢复，必须由用户在「新领域」主动恢复。
- 当前没有 GitHub Actions 等自动发布流水线，构建、签名、覆盖升级、标签和 Release 附件一致性仍需人工验证。
- 正式 APK 沿用本机调试证书（`~/.android/debug.keystore`，证书 SHA-256 `AD:01:E1:…:0A`）。这是历史发布一直使用的证书，换成新的正式证书会让老用户无法覆盖升级，必须由用户明确决定；该文件丢失后也无法再产出可覆盖安装的包。签名密钥、密码、模型 Key 和用户数据不得写入仓库或交接文档。
- 用户要求的组件生成验证应使用 macOS 钥匙串中的 DeepSeek 或 MiniMax 凭据。不要擅自改用本地千问模型，也不要输出 Key 内容。

## 建议的接手顺序

1. 阅读 `AGENTS.md`，再阅读本页和当前任务涉及的产品文档。
2. 查看 `git status`、`git log`、标签、Release 和源码版本，确认没有待提交改动或未发布修复。
3. 按功能从 [架构与代码导航](architecture.md) 定位 UI、ViewModel、Repository、Room 和协议边界。
4. 先复现并记录当前行为；涉及 Compose 交互时在专用模拟器验证触控、滚动、键盘、系统返回和不同字号。
5. 小步实现，补充领域、协议、存储或仪器测试，并同步更新对应长期文档和本交接页。
6. 使用中文提交信息。新版本按贡献指南构建、签名、验证覆盖升级，发布 GitHub Release，并核对附件 SHA-256。
7. 完成或移交前重新检查工作区，确保本页的版本、提交、验证结果、已知限制和未完成项与仓库一致。
